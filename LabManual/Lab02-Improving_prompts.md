# Lab 02：プロンプトを改善する

推定時間: 20分

[演習一覧へ戻る](./README.md) | [演習環境の準備](./00_演習環境を準備する.md)

## 対応する研修テキスト

第2章「生成AIにうまくお願いする方法」

曖昧なプロンプトと、目的や条件を追加したプロンプトを順番に実行し、生成結果の違いを確認します。

## この演習で行うこと

次の3種類の依頼について、改善前と改善後のプロンプトを比較します。

1. 取引先へのメール
2. 会議メモの要約
3. 社内イベントのアイデア

完成した文章の良し悪しを競う演習ではありません。プロンプトのどこを具体的にしたか、その指定が回答へ反映されたかを確認します。

## タスク1 - ビジネスメールのプロンプトを改善する

### 1. 改善前のプロンプトを試す

新しいチャットを開始し、次のプロンプトを送信します。

```text
取引先へのメールを書いてください。
```

生成されたメールを確認します。Copilot Chatには、誰から誰へ送るのか、何を依頼するのか、どのような情報を含めるのかが伝わっていません。

### 2. 改善後のプロンプトを試す

同じチャットで、次のプロンプトを送信します。

```text
あなたは法人営業担当者です。
取引先の田中様へ、打ち合わせ日程の変更をお願いするメールを作成してください。

変更前：8月5日 14時
変更候補：8月6日 10時、8月7日 15時
理由：社内会議との重複

丁寧で簡潔な表現とし、件名を含めて300文字以内で作成してください。
```

### 改善ポイント

| 追加した内容 | プロンプト内の指定 |
|---|---|
| AIの役割 | 法人営業担当者 |
| 相手 | 取引先の田中様 |
| 目的 | 打ち合わせ日程の変更 |
| 前提情報 | 変更前、変更候補、理由 |
| 文体 | 丁寧で簡潔 |
| 出力形式と長さ | 件名を含め、300文字以内 |

### 確認ポイント

- 件名と本文が生成されていることを確認します。
- 変更前の日時と、2つの変更候補が正しく反映されていることを確認します。
- 日程変更の理由が、必要以上に詳しく書かれていないことを確認します。
- プロンプトにない会社名や連絡先が、事実のように追加されていないか確認します。

> **Tips**
>
> 「丁寧に」だけでなく、相手、目的、必要な情報まで伝えると、修正しやすい初稿になります。

## タスク2 - 要約のプロンプトを改善する

### 1. サンプル文章を準備する

[要約用会議メモ](./samples/Lab02_要約用会議メモ.md)を開き、「7月15日に」から始まる本文をコピーします。

### 2. 改善前のプロンプトを試す

新しいチャットを開始し、次のプロンプトの末尾へ会議メモを貼り付けて送信します。

```text
以下の文章を要約してください。

-----
7月15日に、社内FAQサイトの改善会議を実施した。現在、総務部と情報システム部には、社内手続きに関する問い合わせが合計で月120件ほど寄せられている。特に多いのは、パスワードの再設定、経費申請の方法、在宅勤務申請の3種類である。問い合わせ対応の負担を減らすため、まずこの3件のFAQをトップページへ掲載する方針となった。FAQの原稿は総務部が8月20日までに作成し、情報システム部が内容を確認したうえで9月1日に公開する。サイト全体の検索機能も改善候補に挙がったが、改修範囲と費用が明確でないため、次回会議で継続して検討する。
```

回答の長さ、構成、読み手はCopilot Chatが判断します。

### 3. 改善後のプロンプトを試す

同じチャットで、次のプロンプトの末尾へ同じ会議メモを貼り付けて送信します。

```text
以下の文章を、内容を初めて読む部門長向けに要約してください。

出力形式：
1. 結論
2. 重要ポイント3点
3. 確認が必要な事項

本文に書かれていない内容は追加せず、全体を400文字以内にしてください。

-----
7月15日に、社内FAQサイトの改善会議を実施した。現在、総務部と情報システム部には、社内手続きに関する問い合わせが合計で月120件ほど寄せられている。特に多いのは、パスワードの再設定、経費申請の方法、在宅勤務申請の3種類である。問い合わせ対応の負担を減らすため、まずこの3件のFAQをトップページへ掲載する方針となった。FAQの原稿は総務部が8月20日までに作成し、情報システム部が内容を確認したうえで9月1日に公開する。サイト全体の検索機能も改善候補に挙がったが、改修範囲と費用が明確でないため、次回会議で継続して検討する。
```

### 改善ポイント

| 追加した内容 | プロンプト内の指定 |
|---|---|
| 読み手 | 内容を初めて読む部門長 |
| 出力構造 | 結論、重要ポイント3点、確認事項 |
| 長さ | 400文字以内 |
| 禁止事項 | 本文にない内容を追加しない |

### 確認ポイント

- 「結論」「重要ポイント3点」「確認が必要な事項」に分かれていることを確認します。
- 月120件、8月20日、9月1日などの数字が正しく反映されているか確認します。
- 未決事項である検索機能の改修範囲が、決定事項として書かれていないか確認します。
- 原文にない担当者名や予算が追加されていないか確認します。

> **Tips**
>
> 要約では、単に「短くして」と頼むのではなく、「誰が読むのか」「何を判断したいのか」「どの構成にするか」を指定します。

### ファイル追加を利用できる場合

環境によっては、入力欄付近の追加メニューから、会議メモのファイルを追加できます。ファイルを追加した場合は、「対象文章」の貼り付けに代えて、「追加した会議メモを」と指定できます。

ファイル追加が表示されない場合は、本文のコピー＆ペーストで進めてください。基本演習の内容は変わりません。

## タスク3 - アイデア出しのプロンプトを改善する

### 1. 改善前のプロンプトを試す

新しいチャットを開始し、次のプロンプトを送信します。

```text
社内イベントのアイデアを考えてください。
```

提案数、予算、開催方法、出力形式が指定されていないことを確認します。

### 2. 改善後のプロンプトを試す

同じチャットで、次のプロンプトを送信します。

```text
従業員同士の交流を増やす社内イベント案を5つ提案してください。

条件：
- 参加者は50人程度
- 所要時間は60分以内
- オンラインと会場参加を併用
- 予算は1人3,000円以内

「企画名／内容／準備物／注意点」の4列の表で回答してください。
```

### 改善ポイント

| 追加した内容 | プロンプト内の指定 |
|---|---|
| 目的 | 従業員同士の交流 |
| 提案数 | 5つ |
| 制約条件 | 人数、時間、開催方法、予算 |
| 出力形式 | 4列の表 |

### 確認ポイント

- イベント案が5つ提案されていることを確認します。
- すべての案が表で整理されていることを確認します。
- 各案が、人数、時間、開催方法、予算の条件におおむね合っているか確認します。
- Copilot Chatが提案した費用や内容は、確定した事実ではなくアイデアであることを確認します。

> **Tips**
>
> 条件が多いときは、最初に目的を書き、その後に必須条件を箇条書きで並べます。最後に表や箇条書きなどの出力形式を指定すると、プロンプトを読み返しやすくなります。

### 追加プロンプト

タスク1で生成したメールへ、次の修正を依頼します。

```text
先ほどのメールについて、日程変更へのお詫びは残したまま、
本文を200文字以内へ短くしてください。
変更候補の日時は箇条書きにしてください。
```

どこを残し、どこを変更するのかを指定すると、必要な部分だけを修正しやすくなります。

## プロンプト改善のTips

- すべての条件を最初から思いつく必要はありません。回答を見てから条件を追加できます。
- 修正するときは、「残したい部分」と「変更したい部分」の両方を伝えます。
- 数量、文字数、期間、読み手、形式を具体的にすると、回答を比較しやすくなります。
- 指示した形式や数字が守られているかは、人が確認します。
- プロンプトが長くなったら、目的と必須条件を先に書きます。
